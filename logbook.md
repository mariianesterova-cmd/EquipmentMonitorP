# Журнал прийняття рішень (Logbook)

1. Проблема: Вибір легкої СУБД для навчального проєкту без потреби розгортання окремого сервера
   Рішення: Обрано SQLite у поєднанні з Entity Framework Core, що спрощує міграції та перенесення

2. Проблема: Відображення складних статусів обладнання в інтерфейсі (працює, на обслуговуванні, несправне)
   Рішення: Створено Enum `EquipmentStatus` та використано кольорові бейджі (Bootstrap badges) для наочності

3. Проблема: Захист від введення невалідних або дубльованих даних
   Рішення: Додано атрибути валідації `[Required]` у моделі та перевірку унікальності інвентарного номера в контролері

4. Проблема: Необхідність швидкої фільтрації при великій кількості пристроїв
   Рішення: Реалізовано LINQ-запити з комбінованим пошуком за назвою та фільтрацією за статусом

5. Проблема: Організація командної роботи у Visual Studio
   Рішення: Налаштовано гілкову модель Git та роботу через спільний репозиторій GitHub з розподілом обов'язків

6. Проблема: Потреба ізольованого виконання юніт-тестів у CI/CD без прив'язки до фізичної бази даних
   Рішення: Підключено `Microsoft.EntityFrameworkCore.InMemory` для швидкого тестування логіки контролера у пам'яті

7. Проблема: Помилка компіляції (CS1061) та падіння кроку `Build solution` у GitHub Actions під Linux
   Рішення: Додано відсутні асинхронні методи `Edit` (GET/POST) у `EquipmentController.cs` та уніфіковано шляхи у конфігурації `.github/workflows/dotnet-ci.yml`
