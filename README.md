Програмна платформа моніторингу стану обладнання (EquipmentMonitor)

 1. Загальний опис проєкту
Цей вебзастосунок створений для автоматизації обліку та моніторингу технічного стану обладнання в університетській лабораторії. 
Система дозволяє відстежувати наявність пристроїв, їхні місця розташування, дати придбання та поточні статуси.

---

 2. Архітектура та структура програми (Як це працює)
Проєкт побудований за класичним паттерном MVC (Model-View-Controller)** з використанням архітектурного підходу Клієнт-Сервер усередині моноліту .NET:

1. Моделі (`Models/Equipment.cs`):
   - Описують сутність обладнання (`Equipment`).
   - Містять поля: `Id`, `Name` (назва), `InventoryNumber` (інвентарний номер), `Location` (розташування), `PurchaseDate` (дата придбання) та `Status` (статус пристрою).
   - Використовують `enum EquipmentStatus` із трьома станами: `Working` (Працює), `UnderMaintenance` (На обслуговуванні), `Broken` (Несправне).
   - Мають вбудовану валідацію (`[Required]`), яка перевіряє коректність заповнення полів.

2. Контекст Бази Даних (`Data/AppDbContext.cs`):
   - Відповідає за зв'язок із локальною базою даних SQLite за допомогою Entity Framework Core.
   - Автоматично ініціалізує базу даних при першому запуску (`EnsureCreated`) та заповнює її початковими тестовими пристроями (Seed Data).

3. Контролер (`Controllers/EquipmentController.cs`):
   - `Index` (GET): Обробляє запити на перегляд списку, виконує пошук за назвою/інвентарним номером, фільтрує за статусом через LINQ-запити та рахує загальну статистику для інформаційних карток (`ViewBag`).
   - `Create` (GET/POST): Відповідає за додавання нового обладнання. Перевіряє унікальність інвентарного номера (захист від дублікатів) та зберігає дані в SQLite.

4. Інтерфейс (`Views/Equipment/Index.cshtml` та `Create.cshtml`):
   - Використовує HTML/Razor-шаблони та стилізацію Bootstrap.
   - Містить інтерактивні елементи: кольорові бейджі статусів, форму пошуку, панель статистики та зручну таблицю пристроїв.

---

 3. Модульне тестування (Tests)
У складі розв'язку є окремий тестовий проєкт `EquipmentMonitor.Tests` на базі xUnit:
- Перевіряє коректність працездатності валідації моделей (наприклад, переконується, що система не дозволить зберегти обладнання з порожньою назвою).

---

 4. Інструкція з запуску проєкту з нуля (Для перевірки)

Щоб успішно запустити та протестувати роботу застосунку, виконайте такі кроки:

1. Клонуйте репозиторій:
   ```bash
   git clone <https://github.com/mariianesterova-cmd>
2. Запустіть Visual Studio
Оберіть Open a project or solution та відкрийте файл EquipmentMonitor.sln
3. У панелі Solution Explorer проєкт EquipmentMonitor має бути виділений жирним шрифтом (якщо ні — натисніть на нього ПКМ і виберіть Set as StartUp Project).
4. Для запуску застосунку натискаємо зелену кнопку Start або клавішу F5.
5. Застосунок відкриється у браузері. База даних equipment.db та тестові записи створяться автоматично в системі.
6. Ми можемо протестувати функціонал для цього Скористайтеся пошуком або виберіть статус у випадаючому списку.
7. Натисніть кнопку "+ Додати", заповніть форму нового пристрою та натисніть «Зберегти», щоб перевірити роботу CRUD-операцій.
8. У верхньому меню перейдіть у Test -> Run All Tests, щоб переконатися, що модульні тести проходять успішно.
