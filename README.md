# Програмна платформа моніторингу стану обладнання (EquipmentMonitor)

## 1. Загальний опис проєкту
Цей вебзастосунок створений для автоматизації обліку та моніторингу технічного стану обладнання в університетській лабораторії. Система дозволяє відстежувати наявність пристроїв, їхні місця розташування, дати придбання та поточні статуси.

---

## 2. Архітектура та структура програми (Як це працює)
Проєкт побудований за класичним паттерном **MVC (Model-View-Controller)** з використанням архітектурного підходу Клієнт-Сервер усередині моноліту .NET 8:

1. Моделі (`Models/Equipment.cs`):
   - Описують сутність обладнання (`Equipment`).
   - Містять поля: `Id`, `Name` (назва), `InventoryNumber` (інвентарний номер), `Location` (розташування), `PurchaseDate` (дата придбання) та `Status` (статус пристрою).
   - Використовують `enum EquipmentStatus` із трьома станами: `Working` (Працює), `UnderMaintenance` (На обслуговуванні), `Broken` (Несправне).
   - Мають вбудовану валідацію (`[Required]`), яка перевіряє коректність заповнення полів та унікальність інвентарного номера.

2. Контекст Бази Даних (`Data/AppDbContext.cs`):
   - Відповідає за зв'язок із локальною базою даних SQLite за допомогою Entity Framework Core.
   - Автоматично ініціалізує базу даних при першому запуску (`EnsureCreated`) та заповнює її початковими тестовими пристроями (Seed Data).

3. Контролер (`Controllers/EquipmentController.cs`):
   - `Index` (GET): Обробляє запити на перегляд списку, виконує пошук за назвою/інвентарним номером, фільтрує за статусом через LINQ-запити та рахує загальну статистику для інформаційних карток (`ViewBag`).
   - `Create` (GET/POST): Відповідає за додавання нового обладнання. Перевіряє унікальність інвентарного номера (захист від дублікатів) та зберігає дані.
   - `Edit` (GET/POST): Відповідає за безпечне оновлення інформації про обладнання з обробкою помилок паралельного доступу (`DbUpdateConcurrencyException`).

4. Інтерфейс (`Views/Equipment/Index.cshtml`, `Create.cshtml`, `Edit.cshtml`):
   - Використовує HTML/Razor-шаблони та стилізацію Bootstrap.
   - Містить інтерактивні елементи: кольорові бейджі статусів, форму пошуку, панель статистики та зручну таблицю пристроїв.

## 3. Модульне тестування та CI/CD Pipeline
У складі розв'язку є окремий тестовий проєкт **`EquipmentMonitor.Tests`** на базі **xUnit** та **Microsoft.EntityFrameworkCore.InMemory**:
- Перевіряє коректність працездатності валідації моделей (блокування збереження невалідних/порожніх даних).
- Перевіряє роботу методів `EquipmentController` (створення, редагування, повернення `NotFound` для неіснуючих об'єктів).
- Автоматичні тести та збірка проєкту запускаються при кожному push/PR у середовищі Linux `ubuntu-latest` через **GitHub Actions** (`.github/workflows/dotnet-ci.yml`).
